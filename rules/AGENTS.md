# 哈基米哈气审查 (Hakimi Hiss Duel) 自动触发规则

当用户提及以下关键词或意图时，自动激活并使用 `hakimi-hiss` 技能进行编排：
- 「哈基米」「哈气审查」「两只哈基米相互哈气」「hakimi-hiss」
- 「召唤 A 和 B 找 Bug」「比谁找到的 Bug 多」「一胜」「二胜」
- 「A 修 B 的 Bug」「B 修 A 的 Bug」「交叉修复」
- 「啥子标记」「贴上啥子」「查看哈基米战况」「重置哈基米上下文」

执行规则：
1. 创建子代理 A（哈基米A/橘座）与 B（哈基米B/狸花）时，**必须使用当前模型**（`Model: "inherit"`）。
2. 默认审查整个项目；若用户在消息中 `@` 了文件，则严格只审查被 `@` 的文件。
3. 严禁绕过插件通道直接汇总 Bug，必须通过 `hakimi-hiss-channel`（MCP 工具或 `hakimi_channel.py`）完成防重登记、一胜挂起、交叉修复分配、二胜裁决与「啥子」标记。
4. 除非用户明确要求手动重置（`hakimi_reset`），否则始终复用已绑定的 A/B `conversationId`，保持两只哈基米的长期上下文有效。
